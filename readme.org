#+html:<p align="center"><i>Dance around Revit 🩰</i></p>

*Revit Ballet* is a keyboard-first toolkit for Autodesk Revit: 230+ commands for selecting, navigating, editing, documenting and exporting, installed with a single =installer.exe= on Revit 2020 to 2026.

It is built for people who spend their day inside large models and many open sessions, and who want the next action to be two keystrokes and a search box away instead of five ribbon tabs deep.

* What makes it different

- *One scope model everywhere.* Every command says how far it reaches: =InView=, =InDocument=, =InSession= (every open document in this Revit) or =InNetwork= (every Revit session in the peer network). =SelectByCategoriesInSession= does what it says, across all open models, without switching windows.
- *Selections that survive.* Revit only lets you select in the active document. Revit Ballet keeps a persistent selection store keyed by element =UniqueId=, so you can select in one model, switch, and act on it in another. Linked-model elements are first-class.
- *Searchable data grids instead of dialogs.* Results open in one fast grid with a real query language (below). Family, type name, mark and comments are editable in place. Pick rows, and the selection goes straight back to Revit.
- *Everything is invokable by name.* =InvokeAddinCommand= lists every command in the plugin in a searchable grid, =InvokeRevitCommand= does the same for Revit's own commands, and =InvokeLastAddinCommand= repeats the previous one.
- *Sessions talk to each other.* Copy and paste between Revit processes, open a view or sheet that lives in another session, synchronise documents across sessions, copy type parameters between sessions.
- *Scriptable from outside, in three languages.* Each running Revit hosts a local, token-protected server that runs C#, IronPython 2 or CPython 3 inside the session, with a job queue, cancellation and sessions. Scripts, CI jobs and AI agents use the same API (see [[#automation][Automation]]).
- *Tested against real Revit.* Every push builds all seven versions. A separate end-to-end suite installs the plugin into a clean Windows VM with real Revit 2020 to 2026 and checks that it loads and works ([[file:docs/vm-testing.md][how]]).

* Install

Windows 10 or 11 and Revit 2020 to 2026. No admin rights needed: everything goes under your user profile.

1. Download =installer.exe= from the [[https://github.com/baleti/revit-ballet/releases][latest release]].
2. Run it (closing Revit first is best but not required, see below). It finds every installed Revit 2020 to 2026, installs the matching build into each, merges the default keyboard shortcuts into Revit's shortcut file and registers an uninstaller.
3. Start Revit. If Revit asks about an unsigned add-in, choose *Always Load*. Release builds are not yet code-signed.

Good to know:

- *Revit already running?* The installer does not fail on locked files. It stages the update and Revit applies it on the next start.
- *Unattended / scripted installs:* =installer.exe --quiet= (no UI, prints what it did, =--verbosity 0|1|2= for more or less detail). Exit status tells you if it worked.
- *Uninstall:* Windows Settings > Apps > Revit Ballet, or =installer.exe /uninstall=.
- *Offline friendly.* The plugin makes no calls to external servers. Its only listener is the local automation server below.

Details: [[file:docs/installer.md][docs/installer.md]].

*Code signing:* Revit Ballet uses free code signing from the SignPath Foundation (see the [[#code-signing-policy][code signing policy]]). The application is in progress: releases up to 0.9.1 are unsigned, which is why Revit asks about an unsigned add-in on first load.

* Use

A core set of commands is registered under *Add-Ins > External Tools* with default keyboard shortcuts. The installer merges those into Revit's own shortcut file, so you can see and change them in Revit's keyboard shortcut dialog. Every other command is reached through =InvokeAddinCommand=.

- *Find anything:* run =InvokeAddinCommand= (give it a shortcut of your choice). Type part of a name and pick. =InvokeLastAddinCommand= repeats the previous one.
- *Select, then act.* A typical flow: =SelectByCategoriesInView= opens a grid of categories; pick some; =SelectByFamilyTypesInDocument= narrows them; =SetParametersOfInstance= edits them.
- *Grids are the interface.* In any grid, type in the search box to filter, click headers to sort, and edit supported columns in place. The search box speaks the same small query language as the pickers on the author's Linux desktop (=~/.config/docs/query-dsl.md= is its definition):

  - =door fire= : rows containing both words in any column
  - =!glazed= : exclude
  - ="fire door"= : quoted phrase, matched as written
  - =//level L2= : only rows whose column matching "level" contains "L2" (=/fv level:L2= is the same; the column is shown automatically)
  - =//area >50= : numeric comparison on one column (=>=, =<=, =>==, =<==); =!//area >50= inverts it
  - =/ft mark /at level= : choose columns: =/ft= keeps only those, =/at= adds, =/rt= removes (applied left to right)
  - =/s area desc= : sort; =/s/level/mark= sorts by level then mark; =/rv= reverses the order
  - =//selection "my set"= : members of a Revit selection set (a computed column listing the sets an element is in)
  - names match as substrings and ignore spaces: =//"type name" flush= and =//typename flush= are the same

  Changed with this language: =a || b= (OR), =e"exact"=, =*glob*=, a bare =>50=, =2$col= positions and =#set= are gone. Use quoted phrases, scoped comparisons (=//count >5=), the order of =/at=, and =//selection= instead. A column name that matches nothing now shows no rows instead of being ignored.

- *Run commands from outside Revit (optional).* The installer can add a small tray program: press =Win + `= and pick any command from a list that covers every Revit window on this computer (and on other machines you list in =%APPDATA%\revit-ballet\remote.json=, reached with ssh). Same query language, same list as =InvokeAddinCommand=. Off unless you tick it in the installer or pass =--remote-picker on=.
- *Pick the scope you need.* If a command exists as =...InView=, =...InDocument=, =...InSession= and =...InNetwork=, the suffix is the only difference.

** Scopes

| Suffix        | Reaches                                         |
|---------------+-------------------------------------------------|
| =InView=      | the active view                                 |
| =InDocument=  | the active document                             |
| =InSession=   | all documents open in this Revit process        |
| =InNetwork=   | all Revit sessions in the peer network (by default, running on this machine) |

* Automation

Every Revit session runs a small HTTPS server on =127.0.0.1= (ports 23717 to 23817, one per session). Submit a script as a job; it runs inside Revit with the live =UIApp=, =UIDoc= and =Doc= in scope and comes back as JSON. It is how this repository's own end-to-end tests drive Revit, and how AI agents inspect and edit live models.

Three engines, installed as separate optional components (embedded interpreters are what antivirus products flag, so you can leave them out with =installer.exe --engines none=):

| Engine        | Language                | Notes                                                              |
|---------------+-------------------------+--------------------------------------------------------------------|
| =roslyn=      | C#                      | script with full Revit API access                                  |
| =ironpython2= | Python 2.7 (IronPython) | =from Autodesk.Revit.DB import *=, standard library included       |
| =cpython3=    | Python 3.12 (CPython)   | real CPython through pythonnet; runtime bundled, no Python needed  |

#+begin_src powershell
$token = Get-Content "$env:APPDATA\revit-ballet\runtime\network\token"
$body  = @{ engine = "cpython3"; wait = 20000; code = "result = [d.Title for d in uiapp.Application.Documents]" } | ConvertTo-Json
curl.exe -sk -H "X-Auth-Token: $token" -H "Content-Type: application/json" --data-binary $body https://127.0.0.1:23717/v1/jobs
#+end_src

The response carries =state=, =output=, the =value= (as JSON when it is plain data), positioned compile =diagnostics= and a stack trace on errors. Jobs queue in order, can be cancelled (=DELETE /v1/jobs/{id}=), stream their output (server-sent events), and can share state through named sessions. A script stuck behind an open Revit dialog is reported as such instead of silently hanging.

- Loopback only, shared 256-bit token, written under =%APPDATA%\revit-ballet\runtime=.
- Open sessions and their ports are listed in =runtime\documents=; that is also how the =...InNetwork= commands find each other.
- Scripts run with the user's full rights: treat the token like a password.

The wire format is in [[file:docs/agent-protocol.md][docs/agent-protocol.md]]; the conventions agents follow are in [[file:CLAUDE.md][CLAUDE.md]].

* Build from source

Builds on Linux, macOS or Windows with the .NET SDK. The Revit API comes from NuGet, so no Revit install is needed to compile.

#+begin_src sh
bash Build.sh                                   # all Revit versions + installer.exe
dotnet build commands -c Release -p:RevitYear=2025   # one version
dotnet test core/tests                          # unit tests (filter engine, sorting, naming)
#+end_src

The installer embeds every build, so =installer/bin/Release/installer.exe= is the only file you ship. CI builds all seven versions on every push ([[file:.github/workflows/build.yml][workflow]]). =tests/vm/ci.sh= runs the end-to-end suite against real Revit installs in a throwaway VM ([[file:docs/vm-testing.md][docs/vm-testing.md]]).

* Status and contributing

Pre-release (0.9.x): in daily use, command names and shortcuts may still change. Issues and pull requests are welcome. Please read [[file:CLAUDE.md][CLAUDE.md]] first; it documents the naming scheme, the scope rules and the Revit API pitfalls found along the way.

* Code signing policy

Free code signing provided by [[https://signpath.io][SignPath.io]], certificate by [[https://signpath.org][SignPath Foundation]] (application in progress; releases up to 0.9.1 are unsigned).

Once approved, release installers and add-in assemblies are signed from a build made by GitHub Actions from a tagged commit, and every signing request is approved by hand. The roles, what is signed, the privacy statement and the changes the installer makes on your machine are in [[file:docs/code-signing-policy.md][docs/code-signing-policy.md]].
